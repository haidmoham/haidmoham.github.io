Checkpoint lineage

The robot should make its own evolution inspectable.

C-1N is the integration point. The Robotics Test Bench is the experiment source: it isolates physical questions and records the evidence that updates the model. A checkpoint is created only when a capability or understood failure is worth preserving and comparing with prior behavior.

  • C-1N // 00 · SPAWN — historical deterministic six-foot spawn baseline. Its selector replays the locomotion attempt from that era; the checkpoint itself does not claim standing or walking.
  • C-1N // 01 · SHUFFLE — current coordinated gait failure, now carrying the unified simulation and measured-state telemetry without advancing the checkpoint.
  • C-1N // 02 · STAND — reserved for the first support-aware stable stance after static-support and leg-workspace evidence transfers into a repeatable stance-only rollout.
  • C-1N // 03 · STRIDE — reserved for the first materially better sustained walk. It is not a completed checkpoint yet.
Worth noting: Instrumentation can make a failure more legible without turning it into a new capability. Both selectors preserve locomotion playback; their labels still describe the evidence boundary, not a success claim.
