Spider

A six-legged MuJoCo robot that grows only when a small, evidence-backed experiment gives the next change a reason to exist.

View canonical repository ↗Inspect Robotics Test Bench →

Current capability

Coordinated tripod targets

Spider drives two position-controlled hinges per leg from a shared gait phase, torso-orientation feedback, and foot-contact checks.

Observed boundary

Forward motion is not sustained

In this 12-second native rollout, the torso moves 6.7 cm forward but drops 30.0 cm. This is a baseline failure to explain, not a walking claim.

Evidence route

Learn mechanisms first

Coupling, trajectory control, actuator limits, contact, mismatch, and identification experiments inform targeted changes. They are hooks, not a fixed roadmap.

Why this exists

A portfolio artifact should preserve the decision trail.

Spider is the integration point. The Robotics Test Bench remains the place to isolate a physical question and update the model. The Spider repository remains the place to apply a justified change to a full robot.

  • Multi-DOF coupling establishes why leg joints cannot be reasoned about in isolation.
  • Model-based control establishes what feedforward buys and how wrong dynamics leave a structured correction burden.
  • The next Spider change must cite the experiment or observed failure that motivates it.
Worth noting: This is not a generic simulation showcase. The project makes its limits inspectable, so a viewer can separate a controller-imposed pattern from evidence about the mechanism.
