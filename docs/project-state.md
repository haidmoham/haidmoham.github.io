# Public project activity

`project-sources.json` is the explicit source allowlist. Entries come from the portfolio's public project links and robotics provenance. The synchronizer rejects private or renamed repositories. Add other projects only after checking their public source URL. Project selection and order remain editorial decisions.

Run `node scripts/sync-project-state.mjs --check` to read sources without writing files. Run without `--check` to refresh `project-state/`. `GH_TOKEN` is optional locally; an authenticated request has a larger GitHub API limit. Never write the token into a file. Run `node scripts/sync-project-state.mjs --self-test` for the focused generation checks.

The daily and manual `project-state.yml` workflow reads default-branch commit metadata with the GitHub REST API. It produces 28 complete UTC days of commit counts, the latest commit reference, and one SVG per project. The graphic is explicitly a commit-activity chart. It is not a progress score. Every API page must load and every source must validate before the script writes files. Failed requests retain the previous snapshot and fail the workflow. A concurrent push to main makes publication fail safely; a later run can retry from current main.

`project-state/index.json` contains public source links and commit references. `anonymous.json` omits repository URLs, branch names, hashes, names of people, and author details. Neither projection collects commit messages or email addresses. SVGs contain only project labels, dates, and counts. Anonymous labels and activity can still be recognized by someone who already knows a project; this is pseudonymous sharing, not an unlinkability guarantee.

The workflow commits only `project-state/` to main after the site validator passes. Existing hosting integrations can deploy this commit. GitHub does not trigger other Actions workflows from a push made with `GITHUB_TOKEN`; this job runs its own site validation. Confirm the external host's deployment for the generated commit when auditing publication. The prototypes fetch the current canonical snapshot through a same-origin server route. The anonymous route fetches only anonymous.json; it never exposes the canonical upstream address to the browser. Each prototype retains a bundled fallback if the canonical host is unavailable. Do not serve identified JSON through an anonymous host.

The two notebook visuals have explicit evidence entries in `project-sources.json`. Their reviewed revisions come from the published lab pages. The sync compares the current and reviewed Git blob ids for each exact notebook path. `evidence[].sourceChanged` signals a changed input while the published image and its original provenance stay intact. An unchanged notebook does not imply that every other file in its experiment is unchanged. A moved or deleted input fails the sync so that the mapping receives review.

Notebook results, experiment graphics, screenshots, technical descriptions, completion labels, and checkpoint names do not update from commit activity. Those artifacts still require source evidence and review under `.ontology/commit-rules.md`. This job never executes a notebook or source repository. A future visual exporter must declare its inputs, run in the source project's own trusted build, and pass the same supported-experiment publication boundary before this portfolio imports its outputs. To approve a changed notebook visual, inspect its recorded outputs and interpretation, regenerate the export without executing the notebook, verify the visual, and update the manifest's reviewed revision in the same reviewed commit as the visual.

To show the data, read `/project-state/index.json` on the professional site or the anonymous projection on the pseudonymous site. Match a card's id to `projects[].id`. Show the snapshot's `through` date and use `projects[].visual` for the labeled SVG. Preserve the written project description if the request fails. Do not infer project depth, completion, or scientific results from the counts.
